## 1. MR tasks, licence, nnU-Net details
- nnU-Net v2 (V: Dataset### names, plans.json, nnunetv2 imports). PlainConvUNet, ZScoreNormalization, 1 channel "MR", use_mask_for_norm=False, `folds: [0]` -> ONE fold (fold_0 only) per model (V: DEFAULT_CONFIG in map_tasks_config.py).
- Licence (V, README l.59ff): "Openly available for any usage (Apache-2.0 license)": total, **total_mr**, body_mr, vertebrae_mr, liver_segments_mr, liver_lesions_mr, lung_vessels (CT), trunk_cavities (CT: pericardium/mediastinum), etc. "Available with a license (free for non-commercial usage; commercial: contact)": heartchambers_highres, coronary_arteries, aortic_sinuses, appendicular_bones_mr, tissue_types_mr, face_mr, thigh_shoulder_muscles_mr (and CT-only renal_arteries, aorta_annulus, aortic_dissection, pulmonary_artery_landmarks, per `commercial_models` in map_to_binary.py). Commercial weights are not on GitHub: fetched from a licence server with a licence number (V: libs.py download_model_with_license_and_unpack). Do not use for us.
- **total_mr** (V, map_tasks_config.py + plans.json):
  - default 1.5 mm: two models 850 (organs, 29 classes) + 851 (muscles); trainer nnUNetTrainer_2000epochs_NoMirroring; 850 patch (z,y,x)=[112,128,160], spacing 1.5^3, batch 2.
  - fast 3 mm: single model **852**, 50 classes, patch [96,96,128], spacing 3^3, batch 4, 5 stages, base 32 features. fastest 6 mm: 853.
  - Labels (V, dataset.json of 852): 22 heart (whole heart as ONE label), 23 aorta, 24 inferior_vena_cava, 25 portal+splenic vein, 26-29 iliac a/v, 10/11 lung L/R, 12 esophagus, 19 vertebrae, 21 spinal_cord, 34/35 clavicula, 50 brain, plus abdominal organs/bones/muscles. No pulmonary artery, no chambers, no myocardium, no SVC, no coronaries.
- Other MR tasks with weights on GitHub (all 1-fold, Apache): 597 body_mr (1.5 mm), 598 (6 mm), 756 vertebrae_mr, 576 liver_segments_mr, 589 liver_lesions_mr (CT+MR).

## 3. Preprocessing / postprocessing (V, nnunet.py / python_api.py)
- Order: (optional crop) -> `as_closest_canonical` (reorient to RAS+) -> `change_spacing` to isotropic target (1.5/3/6 mm) with order=1 (resampling_order default 1) -> nnU-Net predictor. nnU-Net then does its own z-score over the whole image (mask_for_norm False): (x-mean)/std. No intensity clipping for MR (that is CT-only, via the plans' percentile clip, and absent from MR 'ZScoreNormalization'). Prediction: step_size 0.8 for total/total_v3/total_mr, 0.5 otherwise; tta off by default (disable_tta = not tta), folds [0].
- RED FLAG (V + I): the resampled image is cast with `dtype=np.int32` (nnunet.py l.552) before saving to NIfTI. Feeding float MR magnitude in 0..1 range truncates to 0/1. Scale the input (e.g. to 0-4095 ints) or, in our own Rust pipeline, resample as float; z-score is scale-invariant so scaling is harmless (I).
- Output resampled back to input grid: nearest for labels (order 0), or order 1 on one-hot/probabilities when higher_order_resampling; reorient back via undo_canonical.
- Two-stage structures: (a) total_mr default = two sub-models by label part (850 organs, 851 muscles), merged with `map_taskid_to_partname_mr`; irrelevant if we use 852 (single network, all 50 labels). (b) CT-style triple z-split only if >512*512*900 voxels and multimodel, unlikely. (c) `roi_subset`/crop tasks first run total_mr 3 mm (task 852) to locate organs, then the target model on the crop (crop_addon [20,20,20]); applies to heartchambers_highres (CT, crop ["heart"], addon 5, remove_outside heart/aorta/IVC) but that is commercial.
- Our single-network recipe: 852 only needs RAS reorient + 3 mm trilinear + z-score + sliding window [96,96,128] (z,y,x order of plans; exporter reverses for hasty).

## 4. High-res heart for MR?
No. heartchambers_highres (task 301) is CT only: myocardium, atrium_left, ventricle_left, atrium_right, ventricle_right, aorta, pulmonary_artery; 0.7266x0.7227x1.0 mm; trained on paired contrast+non-contrast CT; commercial licence (V: README, heartchambers_highres_details.md, commercial_models). No `_mr` variant exists in TASK_CONFIGS (V). Same for coronary_arteries, aortic_sinuses: CT, licensed. Also `trunk_cavities` (pericardium, mediastinum, Apache) is CT. Open-weights `total` (CT) has CT heart chambers (V: class_map_part_cardiac) but CT-trained, not for MR.

## 5. Recommendation
1. **Dataset852 (total_mr 3 mm, Apache-2.0)**: aorta (23), IVC (24), whole heart (22), lungs, esophagus, spine, ribs-adjacent bones, in one 120 MB network; 3 mm is coarse (use as ROI/prior, then refine the aorta lumen by our own velocity/magnitude thresholding or 1.5 mm).
2. **Dataset850 (organs part, 1.5 mm, 220 MB)**: same label names for heart/aorta/IVC at 1.5 mm for sharper aorta; patch [112,128,160] (larger inference). Skip 851 (muscles).
- Gaps: no individual chambers, pulmonary artery, SVC, coronaries on MR with an open licence. Realistic options: our own models trained on the synthetic phantoms (Z-Anatomy backbone) for chambers/PA, or ask Wasserthal for a research licence (academic free licence only helps with CT tasks anyway).
- Red flags: int32 cast; labels are 1-based contiguous in dataset.json (background 0), one "heart" label and one "vertebrae"; MR training data are mostly abdominal/whole-body Dixon-like/T1/T2, not magnitude from 4D-flow (I: expect domain shift; check with a bSSFP/magnitude-weighted image first); one fold only, no ensemble; tiny risk the cited dataset licence (Zenodo MR 616 subj) differs from weight licence (not checked).
